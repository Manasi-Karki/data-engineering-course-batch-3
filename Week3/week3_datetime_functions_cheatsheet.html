SQL Date & Time Functions

Almost every analytics question is a question "over time" — trips per day, busiest hour, average ride duration. A timestamp column only does four jobs for you: get bucketed so it's groupable, get a piece pulled out of it, get formatted for a report, or get subtracted from another timestamp to measure a gap. Every example below runs against a small trips table.

Four jobs, four functions

JobFunctionExample
Bucket itDATE_TRUNC(unit, ts)Round down to the start of the day/week/month, so it's groupable
Pull a piece outEXTRACT(field FROM ts)Just the hour, or just the day-of-week, as a number
Format itTO_CHAR(ts, format)A display-friendly string, for a report — not for filtering
Measure a gapts2 - ts1An interval between two timestamps

Try it: same trips table, four functions

Rounds every timestamp down to the start of its day — the standard way to make a moment in time groupable.

Rows 1 and 2 share a day bucket — GROUP BY this column and they collapse into one count

SELECT trip_id, requested_at,
    DATE_TRUNC('day', requested_at) AS trip_day
FROM trips
ORDER BY trip_id;

Pulls one numeric piece out of a timestamp — an hour, a day-of-week — for bucketing or filtering.

DOW is numbered Sunday = 0 … Saturday = 6, not Monday = 1

SELECT trip_id, requested_at,
    EXTRACT(HOUR FROM requested_at) AS hour_of_day,
    EXTRACT(DOW FROM requested_at)  AS day_of_week
FROM trips
ORDER BY trip_id;

Formats a timestamp as a text string for display — not for filtering or grouping.

The format string is case-sensitive with its own vocabulary (YYYY, Mon, HH12, MI…) — it isn't a general string function

SELECT trip_id, requested_at,
    TO_CHAR(requested_at, 'YYYY-MM-DD') AS ymd,
    TO_CHAR(requested_at, 'Mon DD, YYYY HH12:MI AM') AS pretty
FROM trips
ORDER BY trip_id;

Subtracting two timestamps gives an interval; converting that to seconds turns it into a plain number you can average or sum.

Trip 4 has no completed_at — its duration is NULL, not zero

SELECT trip_id, requested_at, completed_at,
    (completed_at - requested_at) AS trip_duration,
    ROUND(
        EXTRACT(EPOCH FROM (completed_at - requested_at)) / 60,
        1
    ) AS duration_minutes
FROM trips
ORDER BY trip_id;

Common mistakes

MistakeWhat goes wrongFix
WHERE requested_at = '2024-03-04'Matches only exact midnight — almost every row on that day is silently excludedUse a range: >= '2024-03-04' AND < '2024-03-05'
WHERE DATE(requested_at) = '2024-03-04'Works, but wrapping the column in a function stops Postgres using a plain index on itPrefer the range form, or index the expression itself
Assuming EXTRACT(DOW ...) counts Monday as 1Postgres numbers Sunday = 0 … Saturday = 6Check the mapping, or use TO_CHAR(ts, 'Day') for a name instead
Averaging completed_at - requested_at directlyThat's an interval, not a plain number — it doesn't behave like one everywhereConvert with EXTRACT(EPOCH FROM ...) before doing math
Forgetting a cancelled trip has completed_at IS NULLAny duration calculation on that row is silently NULLDecide on purpose whether AVG() skipping those rows is what you want
🎯
You're ready when you can look at a raw timestamp column and know whether the question in front of you needs a bucket (DATE_TRUNC), a piece (EXTRACT), a label (TO_CHAR), or a gap (subtraction).
